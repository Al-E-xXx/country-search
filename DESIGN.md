# Country Search — обоснование решения

## 1. Механизм отмены (почему не флаг)

Один `AbortController` создаётся на каждый поиск в `runSearch()`
(`src/search/search-flow.ts:68`) и передаётся до самого транспорта:
`search(query, signal)` → `createCachedSearch` (`src/search/cached-search.ts`) →
`searchCountries` → `fetch(url, { method: 'GET', signal })`
(`src/api/search-countries.ts:24`).

Причины отмены:

| Причина                | Где                                              |
| ---------------------- | ------------------------------------------------ |
| новые символы в поле   | `abortActiveRequest()` (`search-flow.ts:57`)     |
| поле очищено / Escape  | `reset()` (`search-flow.ts:141`)                 |
| ответ не пришёл за 8 с | `controller.abort(reason)` (`search-flow.ts:76`) |

Отличается от флага («запомнить последний запрос и игнорировать поздние ответы»)
тремя вещами:

1. `abort()` рвёт запрос в транспорте: соединение и трафик освобождаются, а не
   досчитываются до конца. С флагом при быстром наборе одновременно висел бы
   запрос на каждый введённый символ.
2. Отмену видят все слои. Кэш не кладёт в память ответ отменённого запроса
   (`cached-search.ts:124`) и рвёт общий запрос, когда от него отвалились все
   ожидающие (`cached-search.ts:148`). Флаг — состояние одного модуля, кэш и
   транспорт о нём не узнают.
3. Отмена не становится ошибкой: `classifySearchError` возвращает `null` для
   `AbortError` (`src/search/error-classification.ts:49`), таймаут отдельным
   `kind: 'timeout'` (`error-classification.ts:52`).

Проверка гонки не маскируется флагом: тест `tears the older request down in the
transport, not only in its own bookkeeping` смотрит в сам транспорт
(`src/search/race-condition.test.ts:319`).

Таймаут сделан через `setTimeout` + `controller.abort(reason)` с
`reason.name === 'TimeoutError'` (`search-flow.ts:71–78`), а не через
`AbortSignal.timeout()`: поведение то же, но внутренний таймер тестов перемотать
нельзя, и тест таймаута ждал бы реальные 8 секунд.

## 2. Задержка набора: 300 мс

`DEBOUNCE_DELAY_MS = 300` (`src/config.ts:8`) →
`debounce(runSearch, DEBOUNCE_DELAY_MS)` (`search-flow.ts:115`). Отсчёт начинается
заново с каждого нажатия, поэтому непрерывный набор даёт один запрос. 300 мс
выбраны между длиной междусимвольной паузы при наборе (100–200 мс) и паузой между
словами (500–1500 мс): промежуточных ответов нет, а остановка «человек закончил»
ищет сразу.

| Задержка        | Что меняется                                                                                                                                                                                                                                                                                                         |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0` мс          | Вызов всё равно остаётся асинхронным (`src/search/debounce.ts:46–50`), так что одно `input`-событие по-прежнему даёт один запуск. Но каждый следующий символ — свой запрос: `south africa` = 12 запросов вместо 1. Правильность не страдает (лишние честно отменяются), нагрузка на сеть, сервер и перерисовки — да. |
| слишком большая | Ответ приходит через секунды после конца набора: интерфейс выглядит сломанным, человек жмёт Enter или чистит поле, и это порождает лишние запросы. `retry()` тоже ждал бы столько же.                                                                                                                                |
| задержки нет    | Вся нагрузка ложится на отмену: `q` параллельных запросов, `q` состояний загрузки, `q` перерисовок списка. Отмена отвечает за корректность, debounce — за нагрузку; заменять одно другим нельзя.                                                                                                                     |

`retry()` идёт мимо debounce (`search-flow.ts:138`): повтор явный, задерживать его
незачем.

## 3. Стоимость операций (Big O)

Обозначения: `n` — стран в ответе, `k` — полей страны, которые читает маппер (15,
приоритет картинок флага — 2), `m` — длина списков `languages`/`currencies`/`borders`,
`q` — длина запроса, `E` — лимит кэша `SEARCH_CACHE_MAX_ENTRIES` = 50.

### `mapCountryResponse` — `O(n·k)`

`search()` в `src/main.ts:12` применяет маппер ко всем `n` странам
(`countries.map(mapCountryResponse)`). На одну страну (`src/api/map-country-response.ts:107`)
— фиксированный набор из 15 обращений к свойствам объекта, `O(k)`; списки
обходятся один раз через `readList(...).map(...)` + `keepText(...)`
(`map-country-response.ts:59–82`) — `O(m)`. Итого время `O(Σ (k + m))` = `O(n·k + Σm)`,
что при ограниченных полях страны пишется как **`O(n·k)`**; память — **`O(n·k)`**
на новый список `CountryView[]`, входной payload не копируется.

### Кэш `createCachedSearch` — `O(1)` амортизированно + `O(q)` на ключ

| Операция                                       | Стоимость                                 | Где                                    |
| ---------------------------------------------- | ----------------------------------------- | -------------------------------------- |
| нормализация ключа `trim().toLowerCase()`      | `O(q)`                                    | `toCacheKey` (`cached-search.ts:64`)   |
| попадание в память                             | `O(1)` в среднем                          | `answers.get` (`cached-search.ts:90`)  |
| проверка свежести по `ttlMs`                   | `O(1)` — одно сравнение                   | `recall` (`cached-search.ts:94`)       |
| отметка «использован» (LRU: `delete` + `set`)  | `O(1)`                                    | `recall` (`cached-search.ts:99`)       |
| запись ответа и вытеснение самой давней записи | `O(1)` — не более одной записи на вставку | `remember` (`cached-search.ts:74`)     |
| дедупликация (`watchers` — `Set`)              | `O(1)` на присоединение и на отписку      | `openRequest` (`cached-search.ts:104`) |
| `size()` / `clear()`                           | `O(1)` / `O(E)`                           | `cached-search.ts:195`                 |

Просроченные записи вычищаются лениво, только запрошенная
(`cached-search.ts:94`), — прохода по всем `E` записям нет. `Map` выбран за порядок
вставки: первый ключ — самый давний, `answers.keys().next()` — `O(1)`; поиск или
сортировка «самого старого» дали бы `O(E)`/`O(E log E)` на запись. Память сверху
ограничена: `O(E·n·k)`.

## 4. Принципы чистого кода

| Принцип                        | Где это видно                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Чистые функции                 | `mapCountryResponse` и помощники `readText`, `readCount`, `readList`, `keepText`, `readFlagUrl`; форматировщики `quoted`, `formatCount`, `cardMeta`, `detailsFacts`, `failureMessage` (`src/ui/render.ts`); `toCacheKey` (`cached-search.ts:64`)                                                                                                                                                         |
| Инъекция зависимостей          | `createSearchFlow`, `createCachedSearch`, `createSearchHistory`, `createSearchView` получают участников аргументами; `history.ts` не трогает `window.localStorage`, его приносит `browserStorage()` (`src/main.ts:21`)                                                                                                                                                                                   |
| Ранние выходы                  | `abortActiveRequest` (`search-flow.ts:54`), `classifySearchError` (`error-classification.ts:49`), проверка `signal.aborted` в обеих ветках (`search-flow.ts:94`, `107`), уже снятый сигнал в `searchCached` (`cached-search.ts:173`), `showHistory` с пустым списком (`render.ts:580`)                                                                                                                   |
| Константы вместо чисел и строк | шесть настроек в `src/config.ts`; подписи `render.ts:72–88`; `NOT_FOUND_STATUS` (`search-countries.ts:5`), `RETRYABLE_STATUS_CODES`/`SERVER_ERROR_FROM` (`error-classification.ts:20–21`), `EMPTY_QUERY` (`search-flow.ts:38`), `DETAILS_PANEL_ID` (`render.ts:90`)                                                                                                                                      |
| Композиция вместо дублирования | `keepText` для языков, валют и границ (`map-country-response.ts:59`); `finish()` снимает таймер в обеих ветках (`search-flow.ts:80`); `abortActiveRequest()` общий для `onInput`, `retry`, `reset`; `follow()` и `openRequest()` — один путь «кто-то ждёт» (`cached-search.ts:104`, `144`); фабрики узлов `createCountryCard`, `createDetailsNodes`, `createHistoryItem` (`render.ts:178`, `255`, `313`) |
| Состояние в одном месте        | `activeController`/`lastQuery` — только в `search-flow.ts:50–51`; `resultsQuery`/`selectedCard`/`feedbackQuery` — только в `render.ts:445–494`; память ответов — только в `cached-search.ts`; список запросов — только в `history.ts`                                                                                                                                                                    |
